## Як тут заведено працювати

**Міграції застосовує користувачка вручну.** CLI Supabase не
підключений. Порядок: написати файл у `supabase/migrations/`, надіслати
його користувачці, дочекатись підтвердження, і лише тоді пушити код.
Схема завжди їде поперед коду — інакше між деплоєм і міграцією
застосунок зламаний.

**Деплой** — пуш у `main`. GitHub Actions проганяє `npm run lint`, потім
`npm test`, і лише тоді збирає й публікує. Якщо перевірки впали, на
проді лишається попередня робоча версія.

**Перед комітом обовʼязково `npm run lint`.** Збірка не перевіряє
звернення до неоголошених імен; двічі саме через це помилка доїжджала
до експлуатації.

**Пуші йдуть від акаунта `evgenia-shetil`.** У системному keychain цього
мака збережений інший акаунт, тому в репозиторії прописаний локальний
`credential.helper`. Якщо пуш дає 403 — це не брак прав, а не той
акаунт.

**Перевірка на живих даних.** Є тестовий акаунт (`TEST_EMAIL` у `.env`),
під ним працюють інтеграційні тести проти справжньої бази:

```
set -a && . ./.env && set +a && npx vitest run tests/integration
```

Тестові дані після перевірок прибирати — акаунт спільний із базою
користувачки, хоч і відділений через RLS.

## Що знати про експлуатацію

- **Резервна копія лише ручна**: «Ще» → «Зберегти копію». Безкоштовний
  Supabase не дає відновлення на момент часу.
- **Реєстрація нових користувачів вимкнена.** Щоб створити акаунт —
  тільки через панель Supabase.
- **Проєкт засинає** після 7 днів без звернень.
- **Застосунок сам помічає нову версію** і пропонує оновитись: збірка
  лишає `version.json`, сторінка звіряє його при відкритті.

## Як працювати з користувачкою

Продуктова дизайнерка, робить застосунок для себе, працює переважно з
телефона. Українською.

- **Інструкції для чужих панелей** (Supabase, GitHub) давати точним
  маршрутом кліків з англійськими назвами пунктів. Опис «знайди
  налаштування» двічі призводив до втрати часу.
- **Тон інтерфейсу** — стримано, без звертання до користувача, без роду.
  Правила в `CLAUDE.md`, розділ «Тон текстів».
- Рішення про продукт ухвалює вона. Її спостереження про «річ у ванній,
  якою вже користуються» виправило помилку в моделі, яку я не бачив.

## Перевірка інтерфейсу

`npm run dev:demo` — застосунок з базою в памʼяті, без входу. Так
проходяться екрани очима в браузері (світла й темна тема, телефон і
планшет). Детальніше — `CLAUDE.md`, розділ «Демо-режим».

## Наступний крок

Міграції застосовані до 0018 включно. Журнал повний: кількість кожного
товару дорівнює сумі його подій, початковий залишок пише тригер бази.
«Ще» → Перевірка обліку показує розбіжності, якщо вони колись зʼявляться.

**Перевірка на телефоні** — `docs/PHONE-CHECK.md`. Єдине, чого не
перевірити без неї: копія через «Поділитись», запуск без мережі з
іконки, галерея, колесо дати.

Що ще відкрито — `BACKLOG.md`, розділ 4.
